흐름 1

AsyncAction_ExperienceReady 4 step

BP 의 WaitForExperienceReady 노드가 GameState 가 늦게 spawn 될 수 있어 4 step state machine 으로 처리.

  1. Step 1: WaitForExperienceReady factory검증State

    BP 가 노드 활성화. UAsyncAction_ExperienceReady 인스턴스 생성, RegisterWithGameInstance 로 GC 방지.

  2. ↓
  3. Step 2: GameState 존재 확인검증Decision

    GameState 가 이미 있으면 step 3 으로. 없으면 GameStateSetEvent.AddUObject 로 spawn 대기.

  4. ↓
  5. Step 3: ExperienceManagerComponent 조회검증State

    GameState 에서 component 가져옴. CallOrRegister_OnExperienceLoaded 등록.

  6. ↓

    이미 로드된 경우 1 frame 지연 (BP delegate 안정성).

  7. Step 4: OnReady BP delegate fire검증State

    BP 의 OnReady 출력 핀 실행. SetReadyToDestroy() 호출.

흐름 2

Loading Screen 표시 흐름

CommonLoadingScreen 이 매 tick ILoadingProcessInterface 를 polling 해 화면 표시 / 숨김.

  1. ILoadingProcessInterface 등록검증State

    LyraExperienceManagerComponent 가 ShouldShowLoadingScreen 구현.

  2. ↓
  3. CommonLoadingScreen polling검증State

    매 tick 모든 ILoadingProcessInterface 구현체에 ShouldShowLoadingScreen 질의.

  4. ↓

    하나라도 true 면 host widget 표시.

  5. Host widget 표시검증State

    W_LoadingScreen_Host 가 viewport 에 띄워짐. host 안에 content widget (LoadingScreenWidget) 표시.

  6. ↓
  7. 로딩 완료 시 host 제거검증State

    ShouldShowLoadingScreen 가 false 반환 시 host widget 제거.

결정

Host widget vs Content widget

로딩 화면을 두 widget 으로 분리한 이유.

  1. 1. Host widget

    viewport 에 직접 붙는 컨테이너. map 전환을 가로질러 항상 떠 있음.

  2. 2. Content widget

    host 안에 차지하는 실제 그림 / 텍스트. 게임마다 다른 디자인 적용 가능.

  3. 3. 분리 이점

    host 가 안정성 (생명 주기 보장), content 가 디자인 (교체 가능). OnLoadingScreenWidgetChanged delegate 로 content 만 교체.

  4. 4. ULyraLoadingScreenSubsystem API

    SetLoadingScreenContentWidget(WidgetClass) 로 content 교체. host 는 그대로 유지.
