GE 적용에서 cue 호출 흐름

GE 가 적용될 때 cue 가 자동 trigger 되는 인과.

  1. GE spec 의 GameplayCues[] 결정검증State

    GE 자산이 GameplayCues 배열에 cue tag 들고 있음.

  2. ↓
  3. GE 적용 시 ASC 가 cue tag fire검증State

    ApplyGameplayEffectSpec 마지막에 InvokeGameplayCueEvent.

  4. ↓
  5. CueManager 가 매칭 GCN 찾기검증State

    ULyraGameplayCueManager 의 tag, asset 매핑. 이미 로드되어 있으면 즉시 실행, 아니면 async load.

  6. ↓
  7. GCN 인스턴스 spawn / 실행검증State

    Burst 는 1 회, Looping 은 OnActive / OnRemove 매칭. VFX, sound, 캐릭터 반응.

결정

delay-load 정책 결정

cue 자산을 언제 로드할지.

  1. 1. LoadAlwaysLoadedCues

    부팅 시 일괄 로드. 자주 사용되는 cue (예: 발자국). 메모리 비용.

  2. 2. PreloadedCues

    Experience 또는 무기 활성화 시 preload. 사용 직전에 미리 로드.

  3. 3. 첫 사용 시 async load

    위 두 분류에 없는 cue 는 첫 호출 때 async load. 첫 회 hitch 가능.

  4. 4. DumpGameplayCues 콘솔 명령

    현재 로드 / 미로드 cue 확인. 메모리 디버깅용.
