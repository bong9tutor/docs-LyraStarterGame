구조

부여 / 활성 / 적용의 3 단

라이라 GAS 학습의 골격. 세 단을 섞으면 "왜 어빌리티가 안 보이는가" 와 "왜 데미지가 안 들어가는가" 가 구분 안 됨.

1부여 (Grant)

AbilitySet 으로 어빌리티 spec / GE / AttributeSet 을 ASC 에 등록. 한 번 일어남.

  • ULyraAbilitySet
  • FLyraAbilitySet_GrantedHandles

2활성 (Activate)

입력 또는 자동 트리거로 어빌리티 spec 이 instance 화되어 실행. 매 활성마다.

  • ActivationPolicy
  • ActivationGroup

3적용 (Apply)

활성된 어빌리티가 GE 를 만들어 attribute 를 변경. 매 GE 마다.

  • UGameplayEffect
  • Execution Calculation

4관계 (Relationship)

어빌리티 간 block / cancel / required / blocked 를 데이터로 표현.

  • ULyraAbilityTagRelationshipMapping

5효과 (Cue)

어빌리티 / 이펙트의 시각·음향 효과. delay-load 정책.

  • ULyraGameplayCueManager
  • GCN_*
흐름 1

ASC, AbilitySet, 활성, GE, AttributeSet 흐름

플레이어가 입력을 눌러 어빌리티가 발동되고 데미지가 들어가기까지의 인과.

  1. PlayerState ASC 초기화검증State

    ALyraPlayerState::AbilitySystemComponent 가 owner = PS, avatar = Pawn 으로 init.

  2. ↓

    PawnExtensionComponent 가 InitState_DataInitialized 시점에 호출.

  3. AbilitySet grant검증State

    PawnData->AbilitySets[] 의 각 set 이 GiveToAbilitySystem 으로 ASC 에 부여.

  4. ↓

    InputTag binding 완료.

  5. InputTag 에서 Ability 활성검증State

    AbilityInputTagPressed 호출, ProcessAbilityInput 으로 spec 찾아 활성.

  6. ↓

    ActivationPolicy / Group 검사 통과.

  7. GE 적용 (예: GE_Damage_Rifle)검증State

    ability 가 GE spec 생성, target ASC 에 적용. execution 이 attribute 계산.

  8. ↓
  9. AttributeSet 변경 + Cue검증State

    HealthSet::Health 감소, OnHealthChanged broadcast. Cue 가 시각 / 음향 효과 재생.

참조

시스템 페이지 경로

3 단과 관계 / 효과 / 페이즈 / 글로벌을 깊이 학습하는 페이지들.

  • asc-init: ASC 초기화 4 경로.
  • ability-set: AbilitySet 부여.
  • ability-policy: 활성 정책 (Policy / Group / Cost).
  • tag-relationships: 태그 관계 매핑.
  • damage-pipeline: 데미지 / 힐 파이프라인.
  • cues: GameplayCue 시스템.
  • game-phase: Game Phase 어빌리티.
  • globals-context: 글로벌 ASC + 컨텍스트 확장.
