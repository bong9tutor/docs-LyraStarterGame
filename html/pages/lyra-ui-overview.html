챕터 브리프

이 챕터의 질문

  • 라이라 UI 의 다섯 책임군은 무엇인가?
  • 한 위젯이 화면에 뜨기까지 어떤 인과를 거치는가?

먼저 알아둘 것

  • CommonUI 는 입력·활성화·스타일의 인프라.
  • 라이라 C++ 는 그 인프라에 정책 (input mode, escape, 컨트롤러 분리) 을 얹는 조율 계층.

구조

다섯 책임군

라이라 UI 의 다섯 시스템과 책임 경계.

1CommonUI

Epic 플러그인. 입력 라우팅 + activatable widget + 스타일 + 입력 액션 매핑.

  • CommonGameViewportClient
  • UCommonActivatableWidget

2CommonGame GameUI Manager

UGameUIPolicy 가 UPrimaryGameLayout 의 UI.Layer.* 4 종을 관리.

  • UGameUIManagerSubsystem
  • ULyraUIManagerSubsystem

3UIExtension 플러그인

HUD.Slot.* 태그 와 activatable widget 매칭. layout 내부 slot 채우기 메커니즘.

  • UUIExtensionSubsystem
  • UUIExtensionPointWidget

4GameFeatureAction_AddWidgets

Experience 활성화 시 layer 와 slot 에 위젯을 데이터로 주입.

  • FLyraHUDLayoutRequest
  • FLyraHUDElementEntry

5GameSettings 플러그인

설정 화면. 라이라 코어 UI 와 분리된 위성 시스템 (본 학습 트랙은 코어 6 페이지에 집중).

  • UGameSetting
  • ULyraSettingScreen
흐름 1

위젯이 화면에 뜨기까지의 흐름

Experience 선택부터 위젯이 화면에 표시되기까지의 인과.

  1. Experience 선택검증State

    ULyraExperienceDefinition 결정 후 ActionSet 활성화.

  2. ↓

    ActionSet 의 Actions[] 중 UGameFeatureAction_AddWidgets 발견.

  3. AddToWorld → extension handler 등록검증State

    UGameFrameworkComponentManager::AddExtensionHandler(ALyraHUD::StaticClass(), ...) 로 HUD 등장 구독.

  4. ↓

    ALyraHUD::BeginPlay 가 NAME_GameActorReady 발송.

  5. Layout push + Widget register검증State

    PushContentToLayer_ForPlayer(LayerID, LayoutClass) 로 layer 에 layout 띄우고, RegisterExtensionAsWidgetForContext(SlotID, Player, WidgetClass, -1) 로 slot 등록.

  6. ↓
  7. UIExtensionPointWidget 이 slot 매칭검증State

    layout 안의 UUIExtensionPointWidget 이 자기 SlotID 와 매칭된 widget 을 표시.

참조

시스템 페이지 경로

위 책임군과 흐름을 깊이 학습하는 페이지들.

  • input-activation: 입력 라우팅, activatable lifecycle, input mode 4 종.
  • hud-manager: ALyraHUD + ULyraUIManagerSubsystem.
  • hud-layout: HUD layout 4 BP + escape menu + 컨트롤러 분리.
  • widget-injection: AddWidgets + UIExtension 매칭.
  • tagged-widget-visibility: tag 가시성 게이팅과 미구현 사실.
  • styles-widgets: Common Style + 라이라 위젯 라이브러리.
