구조

3단 구성도

라이라 캐릭터 mesh 구성. invisible driving mesh 가 평가 주체, visible cosmetic mesh 들이 복제.

1Invisible driving mesh

SKM_Manny_Invis, SKM_Quinn_Invis. pawn 의 main mesh component 에 적용. ABP_Mannequin_Base 가 평가 주체.

  • 화면에 안 보임
  • animation 평가 주체

2Visible cosmetic actor

B_Manny, B_Quinn. 단일 root MeshComponent (SkeletalMeshComponent) 만 갖는 actor. UChildActorComponent 로 pawn 의 mesh 에 attach.

  • visible mesh SKM_Manny 또는 SKM_Quinn

3Copy Pose ABP

ABP_Mannequin_CopyPose. parent = AnimInstance. AnimGraph 3 노드, "Copy Pose From Mesh" 노드 사용. SourceMeshComponent 핀 미연결, attached parent mesh 사용.

  • cosmetic actor 의 mesh 에 적용
흐름 1

한 frame pose 복제 흐름

main ABP 가 invisible mesh 의 pose 를 결정, visible cosmetic mesh 들이 CopyPose ABP 로 그 pose 를 복제.

  1. ABP_Mannequin_Base 평가검증State

    pawn 의 main mesh (SKM_*_Invis) 에 적용된 base ABP 가 ThreadSafe Update, AnimGraph, output pose 산출.

  2. ↓

    invisible mesh 의 bone transform 갱신 완료.

  3. CopyPose ABP 가 attached parent mesh 의 pose 읽기검증State

    cosmetic actor 의 mesh 에 적용된 ABP_Mannequin_CopyPose 의 "Copy Pose From Mesh" 노드가 SourceMeshComponent 미연결 상태에서 attached parent (invisible mesh) 의 pose 를 읽음.

  4. ↓
  5. visible mesh 의 bone 에 복제검증State

    skeleton 호환이므로 bone transform 을 그대로 복사. visible cosmetic mesh 가 화면에 표시.

참조

B_Manny / B_Quinn comment 인용

design intent 가 BP 안 comment 로 직접 적혀 있음. 확인 위치: B_Manny, B_Quinn Blueprint 내부 comment.

"copy the pose across from the invisible 'driving' mesh component since the skeletons are directly compatible"

출처: B_Manny, B_Quinn BP 내부 comment (Monolith 검증 완료)

해석: visible mesh 는 invisible driving mesh 와 skeleton 이 직접 호환되므로 pose 를 복사한다.

같은 의미로 ABP_Mannequin_CopyPose 의 comment: "copy the pose from the parent mesh component that our mesh component is attached to" (attached parent 의 pose 를 복사).

원본 comment 전문: 검증 원장 animation-blueprint-analysis.md 에 보존. 본 페이지는 학습에 필요한 핵심 구절만 인용.
비교

단일 mesh vs 3단 trade-off

visible mesh 한 개만 쓰는 패턴과 라이라의 invisible+visible+CopyPose 3단 패턴 비교.

측면단일 visible mesh3단 (invisible + visible + CopyPose)
mesh 개수11 invisible + N visible cosmetic
animation 평가 횟수1 회1 회 (CopyPose 는 복사만, 평가 안 함)
draw call1N (visible mesh 마다 1)
cosmetic 교체전체 mesh 교체 + 재바인딩cosmetic actor 만 교체, invisible mesh 그대로
modular part (head / jacket)같은 mesh 안에 통합 필요각각 별 cosmetic actor 로 추가
retarget 호환visible mesh skeleton 의존invisible mesh skeleton 하나로 모든 cosmetic 호환
설계 의도: draw call 과 메모리는 비용이지만, cosmetic 교체와 modular part 가 자유로워지는 이득이 더 큼. 라이라는 캐릭터 외형을 게임플레이와 격리해 다루는 것이 핵심.
레시피

새 cosmetic part 추가 레시피

head, jacket, hands 같은 modular cosmetic part 추가 순서.

  1. 1. Cosmetic 태그 정의

    Cosmetic.* 네임스페이스 아래 새 tag 등록 (예: Cosmetic.Helmet.Soldier).

  2. 2. mesh rule 등록

    CharacterParts 컴포넌트의 mesh entry 배열에 RequiredTags = {새 tag}, mesh = SKM_Helmet_Soldier 추가.

  3. 3. cosmetic actor BP 작성

    B_Manny 패턴 따라 단일 root MeshComponent 만 갖는 actor. ABP_Mannequin_CopyPose 또는 part 전용 CopyPose ABP 적용.

  4. 4. spawn 흐름 확인

    cosmetic tag set 에 새 tag 추가 시 SpawnActorForEntry 가 UChildActorComponent 로 새 actor 생성하고 owner mesh 에 attach 되는지 in-editor 확인.

  5. 5. pose 복제 확인

    캐릭터 idle / cycle 에서 part 가 driving mesh 의 pose 를 따라가는지 시각 확인.
