결정

Directories vs SpecificAssets

type 의 자산 위치 지정 두 방식.

  1. 1. Directories 사용

    지정 디렉토리 아래 모든 자산 자동 indexing. 일반 게임플레이 자산 (PawnData, Experience).

  2. 2. SpecificAssets 사용

    명시한 자산만 indexing. Map type 이 FrontEnd / DefaultEditor 만 cooking 대상으로 좁힘.

  3. 3. Directories 비움 + plugin 자동 발견

    LyraExperienceActionSet 은 Directories 가 비어 있지만 GameFeature plugin 측에서 자동 발견. plugin 의 AddedAssetTypes 가 그 역할.

  4. 4. bHasBlueprintClasses

    true 이면 BP 파생 클래스도 indexing 대상. Experience / PawnData / Item / Weapon 은 BP override 위해 true.

  5. 5. CookRule

    AlwaysCook 으로 두면 dependency 분석과 무관하게 cooking. Map / GameData 등 boot 필수에 적합.

참조

엔진 기본 type 제거 + 라이라 추가 패턴

엔진이 기본 등록하는 2 type (Map, PrimaryAssetLabel) 을 - 로 제거 후 라이라 정책으로 + 추가.

  • -PrimaryAssetTypesToScan=(PrimaryAssetType="Map", ...): 엔진 기본 제거.
  • +PrimaryAssetTypesToScan=(PrimaryAssetType="Map", SpecificAssets=("/Game/System/FrontEnd"), ...): 라이라 정책 추가 (cooking 범위 축소).
  • -PrimaryAssetTypesToScan=(PrimaryAssetType="PrimaryAssetLabel", ...): 사용 안 함.
왜: 엔진 기본은 Game/ 전체 Map indexing 으로 cooking 비용 증가. 라이라는 FrontEnd / DefaultEditor 만 cooking 하고 in-game map 은 Experience 기반 로드.
