챕터 브리프

이 챕터의 질문

  • ActivationPolicy 3 종은 무엇이 다른가?
  • ActivationGroup 가 동시 활성을 어떻게 제어하는가?
  • InputTag 가 어떻게 어빌리티 활성으로 이어지는가?
  • AdditionalCosts 3 종은 무엇을 검증하는가?

먼저 알아둘 것

  • 같은 ASC 에서 여러 어빌리티가 동시 활성 가능. 그룹이 그것을 제한.
  • 실패는 태그 (Ability_ActivateFail_*) + 메시지 + montage 로 표시.

ActivationPolicy 3 종

ELyraAbilityActivationPolicy enum. 어빌리티가 언제 활성되는지.

policy활성 시점전형 사용
OnInputTriggeredInputTag 입력 시 1 회 활성Melee, Reload, Dash
WhileInputActiveInputTag 누르고 있는 동안 유지Sprint, Crouch, ADS
OnSpawnASC 초기화 직후 자동 활성passive ability (예: regen)
참조

ActivationGroup 3 종

ELyraAbilityActivationGroup enum. 동시 활성을 그룹 단위로 제어.

group동시 활성 정책전형 사용
Independent제한 없음 (다른 ability 와 동시 활성)passive, Reload
Exclusive_Replaceable같은 그룹 활성 시 기존 ability 가 취소되고 새 ability 활성Dash, Sprint
Exclusive_Blocking같은 그룹 활성 중에는 새 ability 활성 차단Death, Reset
구현: ASC 가 ActivationGroupCounts[] 로 그룹별 활성 카운트 관리. IsActivationGroupBlocked 가 새 활성 차단 결정.
흐름 1

InputTag 라우팅 흐름

키 입력이 어빌리티 활성으로 이어지는 인과.

  1. InputComponent, InputAction, InputTag검증State

    EnhancedInput 의 InputAction 에 InputTag 매핑.

  2. ↓
  3. AbilityInputTagPressed 호출검증State

    ASC 가 InputTag 와 spec 의 DynamicAbilityTags 매칭. 매칭된 spec 리스트.

  4. ↓
  5. ProcessAbilityInput (다음 tick)검증State

    tick 시점에 누적된 input 일괄 처리. TAG_Gameplay_AbilityInputBlocked 검사.

  6. ↓

    ActivationGroup / TagRequirement / Cost 검사.

  7. TryActivateAbility검증State

    통과 시 ability instance 생성, ActivateAbility 실행. 실패 시 ClientNotifyAbilityFailed RPC.

참조

파생 어빌리티 4 종 + 실패 처리

라이라가 ULyraGameplayAbility 위에 만든 파생 + 실패 표시.

  • ULyraGameplayAbility_Death: GameplayEvent_Death 트리거 자동 활성. Exclusive_Blocking.
  • ULyraGameplayAbility_Jump: 점프 처리.
  • ULyraGameplayAbility_Reset: GameplayEvent_RequestReset 트리거. 라운드 리셋.
  • ULyraGameplayAbility_FromEquipment 또는 _RangedWeapon: 장비 / 무기 ability. GetAssociatedEquipment. ELyraAbilityTargetingSource 6 종.
  • 실패 처리: FailureTagToUserFacingMessages 가 UI 메시지, FailureTagToAnimMontage 가 실패 montage.
